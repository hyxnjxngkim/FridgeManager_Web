## 단계별로 알게 된 것

1. **코드 점수(R1)는 재료형에서 효과가 큼**: 재료형 19/25 → **25/25**. 벡터만 쓰면 그 재료를 안 쓰는 비슷한 레시피가 섞이는데,
   "임박 재료를 쓰는가"로 다시 줄 세우니 다 맞음. Claude 없이 질문당 0.11초.
2. **질문 재작성(R3)은 문장형에서 효과가 큼**: 문장형 19/25 → **25/25**. "얼큰한 국물 요리" → 태그 `국&찌개, 매운맛`.
   **하지만 묻지 않은 태그를 덧붙이는 문제**가 있었음: "시금치" → `반찬, 다이어트, 고단백`, "닭가슴살, 매운 건 싫어" → `일품, 고단백, 다이어트`.
   이 태그가 검색어 글에 들어가 후보 30개가 "다이어트 반찬"으로 채워지고, 시금치·콩나물 질문은 레시피가 **1개씩만** 나옴.
3. **후보 늘리기(R7)로 결과 부족이 사라짐**: 결과가 3개보다 적으면 후보를 30 → 100 → 300 으로 늘려 다시 찾음.
   결과 3개 미만 2 → **0**, Precision 0.88 → 0.91. 같은 검색어 임베딩을 다시 쓰니 Claude·Titan 추가 호출 없음.
4. **엄격한 재작성(R8)이 가장 좋음**: 요청문에 "요청에 직접 드러난 조건만, 근거 없으면 빈 목록, '~ 싫어'는 태그로 넣지 말 것" 규칙과
   예시 4개(실험 질문에 없는 것)를 넣고, **재료 목록 질문은 재작성하지 않음**.
   Precision 0.91 → **0.97**, 요리 종류 수 1.26 → 1.70(덜 몰림), Claude 호출 절반(재료형 25개는 안 부름), 0.83초 → 0.51초.
   예: "시금치" → 재작성 안 함 → 시금치들깨무침·시금치비트무침, "닭가슴살, 매운 건 싫어" → 태그 없음.
5. **태그를 검색어 글에서 빼는 것(R9)은 오히려 나빠짐**: 49, 0.90. 태그가 정확하면 레시피 임베딩 글(메뉴명 + 재료 + **태그**)과
   잘 맞아서 검색을 돕기 때문. 문제는 태그 자체가 아니라 **근거 없는 태그**였음 → R8 로 해결.
6. **HyDE(R4)는 재작성보다 못함**: 가짜 레시피가 요리 하나로 좁혀져서 다른 정답을 놓침.
7. **BM25 합치기(R2)·거리 임계값(R5)·MMR(R6)은 효과 없음**: BM25 는 문장형에서 약하고(BM25만 쓰면 결과 0개인 질문도 있음),
   임계값은 유사도 크기가 질문마다 달라서(1위 0.23~0.50) 하나의 값으로 못 정함, MMR 은 다양성 대신 정확도가 내려감.

## 한계 (결과를 볼 때 감안할 것)

- **정답 조건이 태그 기반이라 재작성에 유리함**: 재작성도 같은 태그 목록에서 고르고, 레시피 임베딩 글에도 태그가 들어 있음.
- **요리 종류는 API 분류 그대로**: "한 그릇 요리"에 포니언 스프·삼색샌드위치, "디저트"에 감자주스·라떼가 정답으로 채점됨.
- **"~ 말고"는 아직 못 함**: "맵지 않은 국"에 김치찌개가 섞임. 검색 함수에 '빼고 싶은 태그'가 없어서 (다음 개선 후보).
- **Hit@3 은 쉬운 지표**: 그래서 Precision@3 과 '결과 3개 미만'을 같이 봄.
- **질문 50개**: 1~2점 차이는 우연일 수 있음. 크게 벌어진 R0→R1, R1→R3, R3→R7→R8 만 결론으로 씀.
- 재작성·HyDE 는 Claude 출력이라 실행마다 조금 다를 수 있어, [llm_cache.json](llm_cache.json) 에 저장한 출력으로 고정함.
