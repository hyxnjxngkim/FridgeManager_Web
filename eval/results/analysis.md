## 단계별로 알게 된 것

1. **코드 점수(R1)는 재료형에서 효과가 큼**: 재료형 19/25 → **25/25**. 벡터만 쓰면 비슷한 분위기지만 그 재료를 안 쓰는 레시피가 섞이는데,
   "임박 재료를 쓰는가"로 다시 줄 세우니 다 맞음. Claude 호출 없이 질문당 0.11초.
2. **질문 재작성(R3)은 문장형에서 효과가 큼**: 문장형 19/25 → **25/25**, Precision 0.73 → 0.91.
   "얼큰한 국물 요리" → 태그 `국&찌개, 끓이기, 매운맛` 으로 바뀌어, 레시피 임베딩 글(메뉴명 + 재료 + **태그**)과 잘 맞음.
   대가: 질문당 Claude 1번, 0.11초 → 0.83초.
3. **HyDE(R4)는 재작성보다 못함**: 45 vs 50. 가짜 레시피가 구체적인 요리 하나로 좁혀져서 다른 정답을 놓침.
4. **BM25 합치기(R2)는 효과 없음**: 43 (오히려 1 내림). BM25만 쓰면 재료형은 24/25 로 좋지만 문장형이 14/25 로 약해서,
   벡터에 섞어도 이득이 없었음.
5. **거리 임계값(R5)은 효과 없음**: 유사도 크기가 질문마다 달라서 (1위 기준 0.23~0.50) 하나의 값으로 정하기 어려움. 0.2 부터는 정답을 버림.
6. **MMR(R6)은 다양성과 정확도를 맞바꿈**: 요리 종류 수 1.26 → 1.42 로 늘지만 Precision 이 0.91 → 0.88 로 줄어서 규칙상 남기지 않음.
   재작성은 결과가 한 종류로 몰리는 경향(요리 종류 수 2.12 → 1.26)이 있어, 다양성이 중요하면 λ=0.7 이 절충안.

## 한계 (결과를 볼 때 감안할 것)

- **정답 조건이 태그 기반이라 재작성에 유리함**: 재작성도 같은 태그 목록 안에서 고르고, 레시피 임베딩 글에도 태그가 들어 있음.
  그래서 문장형 25/25 는 "태그로 바꾸면 태그 조건을 잘 맞춘다"는 뜻에 가까움.
- **요리 종류는 API 분류 그대로**: "한 그릇 요리"에 포니언 스프·삼색샌드위치, "디저트"에 감자주스·라떼가 정답으로 채점됨 (분류가 `일품`·`후식`).
- **Hit@3 은 쉬운 지표**: 3개 중 하나만 맞아도 1. 그래서 Precision@3 을 같이 봄.
- **재작성은 "~ 말고"를 표현 못 함**: "맵지 않은 국"에서도 김치찌개가 섞임 (검색 함수에 '빼고 싶은 태그'가 없어서).
  재작성이 묻지 않은 태그를 덧붙이기도 함 (예: "닭가슴살, 매운 건 싫어" → `고단백, 다이어트`).
- **질문 50개**: 1~2점 차이(R1 44 vs R2 43 등)는 우연일 수 있음. 크게 벌어진 R0→R1, R1→R3 만 결론으로 씀.
- 재작성·HyDE 결과는 Claude 출력이라 실행마다 조금 다를 수 있어, [llm_cache.json](llm_cache.json) 에 저장한 출력으로 고정함.
